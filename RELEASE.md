# Релиз приложения сотрудника Stoox (обновление «само предложит»)

Репозиторий релизов: **https://github.com/GriZZli1975/employee_app**

Репозиторий должен быть **публичным** — иначе телефоны без GitHub-логина не смогут читать `releases/latest` (будет 404).

При старте экрана «Домой» приложение запрашивает:

```http
GET https://api.github.com/repos/GriZZli1975/employee_app/releases/latest
```

Если в релизе `build` (или semver) **новее**, чем в установленном APK — диалог «Обновить» → скачивание APK из assets релиза.

Код: `lib/core/app_update.dart`.

---

## Версия в коде

В `pubspec.yaml`:

```yaml
version: 1.0.14+16
#        ^^^^^^  ^^
#        имя     versionCode (Android) — только растёт!
```

Перед каждой сборкой для выкладки **обязательно** поднять хотя бы `+build` (например `+16` → `+17`).

## Как выложить новую версию (чеклист)

### 1. Правки в коде

- Сделать фичи/фиксы в `mobile/stoox_employee_app` (этот монорепо или клон `employee_app`).
- Поднять `version` в `pubspec.yaml`.

### 2. Собрать и выложить одной командой

```powershell
cd mobile/stoox_employee_app
.\tool\build_release.ps1 -Publish -Force -Notes "- что нового"
```

Скрипт копирует проект в `C:\temp\stoox_employee_app_build` (в папке OneDrive сборка падает: OneDrive держит файлы `build/` и `.dart_tool/`), собирает APK, **проверяет подпись** и создаёт GitHub Release с тегом `v<version из pubspec>`. Без `-Publish` — только сборка, APK в `C:\temp\stoox_employee_app_build\dist\`. Без `-Force` — обновление можно отложить.

### Подпись APK — не терять ключ

Все выпущенные APK подписаны одним ключом (SHA-256 `7d05b643…1c4706`). Если подписать другим — у механиков обновление **не встанет поверх**, придётся удалять приложение и логиниться заново.

- Ключ: `android/keystore/stoox-release.jks`, пароли: `android/key.properties`. В git не попадают (`android/.gitignore`), лежат в OneDrive — это облачная копия.
- Держите **вторую копию** обоих файлов вне OneDrive (флешка / менеджер паролей).
- Без `key.properties` release-сборка остановится с ошибкой — случайно подписать чужим ключом нельзя. Скрипт дополнительно сверяет отпечаток.
- На новом компьютере: скопировать оба файла в те же пути.

### 3. GitHub Release (вручную, если без скрипта)

1. Открыть https://github.com/GriZZli1975/employee_app/releases/new  
   (или `gh release create` после `gh auth login`).
2. **Tag:** `v1.0.14+16`  
   Формат: `v` + то же, что в `pubspec` (`version+build`).  
   Так приложение надёжно сравнивает и имя, и build.
3. **Title:** например `1.0.14 — список «В работе», смах работ`.
4. **Description:** что нового для механиков.  
   Чтобы **нельзя было закрыть** диалог без обновления, добавьте в текст:

   ```text
   [force]
   ```

5. **Attach binaries:** прикрепить `stoox-employee-1.0.14.apk` (обязательно `.apk`).
6. Publish release (**не** draft, **не** pre-release — иначе `latest` может не отдать).

### 4. Проверка

1. На телефоне со **старой** версией открыть приложение (после входа).
2. Должен появиться диалог с новой версией.
3. «Обновить» → браузер/загрузка APK → установить поверх.
4. После установки диалог больше не должен появляться (пока не выйдет ещё более новый релиз).

## Правила для агента / на будущее

| Что | Куда |
|-----|------|
| Исходники (в монорепо) | `Telegramm_BOT/mobile/stoox_employee_app` |
| Репозиторий + Releases | `GriZZli1975/employee_app` |
| Манифест версии для приложения | **GitHub Release tag + APK asset**, не отдельный сервер |
| Обязательное обновление | строка `[force]` в body релиза |
| Сравнение | сначала `build` из tag `…+N`, иначе semver `1.0.14` |

Репозиторий **должен быть публичным** (или latest доступен без auth). Иначе API вернёт 404/401 и проверка молча пропустится.

Не класть в приложение GitHub token.

## Частые проблемы

| Симптом | Причина |
|---------|---------|
| Диалога нет | Нет release / draft / нет asset `.apk` / tag без номера |
| «Обновить» открывает страницу, но не APK | В релизе не прикреплён `.apk` — берётся `html_url` страницы |
| Установка как новое приложение / «Приложение не установлено» | Другой `applicationId` или другой keystore |
| Сборка падает в папке OneDrive (`app.dill`, не удаляется `build`) | Собирать через `tool\build_release.ps1` (сборка в `C:\temp`) |
| Старая версия «новее» | Забыли поднять `+build` в pubspec перед сборкой |
